Key ones: six preset slots (three locked Built-ins 50/10, 25/5, 45/15 + three user slots), all managed in the card; Continue grayed for the whole break then self-enables at the wall-clock deadline and waits indefinitely; Skip = two-click confirm, always available during break; Delay Break = repeatable +5 min; cycle = 4th work block's break is Large (auto rule ≤6→20, 7–12→30, ≥13→40, per-preset override); MPRIS pause at break start, never auto-resume; chime at break start; "Disable for now" → re-enable = fresh Default Preset (★); wall-clock deadline persistence across reboots. SPEC-003: Presence = unlocked session (no input proof); Auto-start after the Presence window (default 5 min, 1–60) from Idle, and from Disabled only after a lock re-arms it; one desktop notification, no chime; a lock pauses a Work Block and its Desk Reminder (frozen remaining time, persisted), resume on unlock; Breaks keep their wall-clock deadline.

Architecture: single plasmoid; state machine in `plasmoid/contents/ui/pomodoro-machine.js` (pure, the one test seam, 107 test functions in `tests/tst_machine.qml`, run with `QT_QPA_PLATFORM=offscreen /usr/lib/qt6/bin/qmltestrunner -input tests/tst_machine.qml` — PATH `qmltestrunner` is Qt5, never use it). Overlay is widget-owned LayerShellQt (Overlay layer) after live probes killed the KWin-script route (see ADR-0002 before proposing any overlay change). Chime = QtMultimedia MediaPlayer (SoundEffect is WAV-only; theme ships .oga only). Presence and the auto-start notification are Loader-wrapped D-Bus adapters (`PresenceMonitor.qml`, `Notifier.qml`): ScreenSaver `GetActive`/`ActiveChanged` on the session bus, logind `LockedHint` on the system bus as the fallback, both polled once per second; the monitor's observation retry is covered by `tests/tst_presence.qml`.

## Review trail

Independent fresh-context review returned FAIL with 3 blockers (dead UI: `Plasmoid.expanded` misuse + missing module import; overlay not reopening after plasmashell restart; chime fed Ogg to a WAV-only decoder) + 7 non-blocking. All 10 resolved and re-verified (suite 27/27, qmllint clean, no stray `Plasmoid.*` without import, `kpackagetool6` install rc=0). `startPreset` gained a from-idle guard, TDD'd (red→green) with `test_startPreset_refusedOutsideIdle`.

Round 3b (suite unblock + review P2s): the `tst_full.qml` qmltestrunner freeze was **not** a QML/i18n issue. Root cause: QtTest writes `~/.config/qmltestrunnerrc`; where `~/.config` is read-only, KConfig escalates to a blocking `kdialog --msgbox` on the GUI thread, which headless never closes and deadlocks the QML loader-thread handshake (the `QObject::installEventFilter(): Cannot filter events for objects in a different thread` QWARN is a benign marker printed just before the freeze). `scripts/check.sh` therefore exports `XDG_CONFIG_HOME` to a throwaway writable dir and caps each test stage at 60 s. The unqualified `i18n()` in `FullRepresentation` resolves under the test runner (the `kf.i18n: Domain is not set` warnings are untranslated-but-working noise) — no shim was added. Reviewer P2s: README Configure-dialog/cycle-length claims corrected; per-preset explicit large-break editing recorded as consciously deferred (README + SPEC-002 amendment); `deleteUserPreset` resets the star to Built-in slot 0 when the starred slot is deleted (red→green: `test_deleteUserPreset_starredSlot_resetsStarToBuiltin`, guard `test_deleteUserPreset_nonStarredSlot_keepsStar`).

SPEC-003 round (Presence auto-start / lock-paused Work Blocks): first independent review returned FAIL on the Spec axis (Standards PASS) with 3 blockers — the monitor could swallow the first lock observation, the documented logind `LockedHint` fallback was missing, and the README DPMS consequence was inverted — plus paused Delay Break, desk-at-lock, availability-gate and docs findings. All resolved test-first: `tests/tst_presence.qml` retry/recovery contract; machine tests for the paused Delay extension, the desk-at-lock prompt, `startBreakNow` refusal, availability clear, the disabled re-arm after an outage, and the work-deadline-at-lock Break anchor; the monitor now falls back to logind over `SystemBus` and resets its observation cache on an outage; the card disables the end-work controls while paused; README/CONTEXT/HANDOFF/SPEC-003 corrected. A second bounded review verified the original blockers resolved but found the availability-recovery P1 (stale dedup) and boundary/docs P2s; those are fixed in the same pass. A third bounded review passed both axes (Standards, Spec) with two P2 notes; both are closed in the final candidate: a lock observed after an availability outage now pauses a still-running Work Block (new machine test `test_screenLocked_afterRecovery_stillPausesRunningWork`), and the dead Disabled no-op in `screenLocked` was removed.
